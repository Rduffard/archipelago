# Progression UX

Progression UI should make the player feel the difference between becoming broadly more capable and becoming more distinctive.

## Communication Goals

The player should understand:

- Core Checks are the numbers they roll.
- Specialties are the techniques that change what they can do with those rolls.
- unlocked Specialty ranks continue to matter.
- future ranks are visible as aspiration, not as inline clutter.

## Information Hierarchy

Show the most decision-relevant data first:

1. What can I improve right now?
2. What does it cost?
3. What changes if I take it?
4. What does it unlock next?
5. What requirements block me?

This order applies to both Core Checks and Specialties, but the visual language should differ.

## Core Check UX

Core Checks should feel like stat progression:

- numeric values
- linked Attribute formulas
- plus/minus investment controls
- clear point cost
- direct roll implication

## Specialty UX

Specialties should feel like mastery:

- ranks instead of raw stat values
- active rank pips or Roman numerals
- current title and short identity line
- tooltip detail for unlocked effects
- next unlock preview

Avoid presenting Specialties as smaller Core Checks.

## Density Rule

The main progression screen should stay scannable. Long rules text belongs in tooltips, drawers, focused detail panels, or future specialization tree views.

Do not solve density by hiding meaning. Solve it by placing the right detail at the right disclosure level.
