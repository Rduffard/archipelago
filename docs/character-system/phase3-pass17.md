# Sanguine Archipelago — Phase 3, Pass 17
## Generic feature activation contract

The persistent sheet uses the existing typed ability and damage commands for feature activation. The audit found 55 Path features with generic action metadata. Fifty-four expose one or more typed `ability.activate` options and Unbroken Current resolves inside `health.damage`. The generic frontend activation and ending controls were dormant in the sole mounted instance of `FeatureActions.jsx`. This pass removes them and wires the remaining restoration and Initiative recovery buttons directly to their existing command types.

## Authenticated and direct runtime callers

The Archipelago router authenticates requests and the character route validates the ID. The handler validates the envelope, hashes its canonical content, and authorizes the actor before receipt lookup. A matching receipt replays the saved response. Reuse with a different digest returns 409 `operation_conflict`. A fresh request with a stale document revision returns 409 `revision_conflict` before operation payload validation. Commands apply to a clone, expire timed effects according to the existing clock, validate resulting runtime and equipment, and persist changes with an owner and revision predicate. The response and receipt commit in the same transaction. Resource command type allowlists and the typed ability and effect payload checks reject `use-feature`. No new command or backend production code was needed.

## Direct runtime behavior and inventory

`use-feature` has one data-driven branch and two extra cost branches. It accepts feature IDs replayed into the current summary with `action` metadata, requiring the owning Path and at least the listed Calling level. It spends the listed pools, appends `{ featureId, name, note }`, and drops the oldest entry if the list exceeds 100. It increments the runtime revision once. It checks neither action type nor incapacitation. It has no printed effect duration, replacement by feature ID, or gameplay effect application beyond its costs and note. Existing effects are left in place, including an earlier record of the same feature. Direct callers can end records by feature. The typed commands apply the actual effects and durations in their own handlers.

Blood Price additionally costs twice Training bonus in Health. Measured Sacrifice additionally costs six Health and recovers up to two Sorcery Points, capped at the pool maximum. Both require at least one Health after payment. Direct calls validate saved state and revision before dispatch, then feature eligibility, note shape, pools, and applicable Health thresholds in that order. Failed operations leave input state unchanged. Direct calls have a runtime revision and no document revision, owner check, or receipt.

## Before-edit characterization and regression replay

Before changing production code, a deterministic direct-runtime probe used seven scenarios for each of the 55 features. It captured the initial state and the full next runtime or error for a fresh use, the preceding Calling level, an empty primary pool, incapacitation, an existing action-expiring record of the same feature, an invalid note, and a stale runtime revision. All 385 observations matched after the edit. The serialized SHA-256 was `16bbfadf055e694fc460a589702343c5ca32ce4ac9de0db3c4a1156b84ff23fe` both times.

The typed Measured Sacrifice characterization ran before and after the edit. The direct operation preserves an existing action-expiring effect and adds a feature note. The typed Bonus Action rejects incapacitation, spends six Health and one Transfusion use, recovers only available Sorcery Point capacity, removes prior effects marked `endsAfterAction`, and returns the existing result fields including `healthLost`, `sorceryRecovered`, `recordOnly`, and the result's effect descriptor. The typed activation does not append a persistent effect. It has no numeric Bonus Action debit or availability check. This pass preserves that behavior. Whether to introduce a tracked Bonus Action budget is a gameplay decision for the broader action economy.

The transaction fixture confirms that five generic activation shapes reject without changes or receipts. It covers a bare `use-feature` command and payloads under `ability.activate`, `effect.end`, `resource.adjust`, and `resource.convert`. Outsiders receive 404, fresh owner requests receive 422, and stale owner requests receive the established revision conflict. Typed Measured Sacrifice commits both revisions and a single receipt, replays the identical saved response, rejects operation ID reuse with a different payload, and authorizes before replay. Receipt and saved state assertions use the handler's transaction fixture.

Replayed all 32 Pass 16 routing cases with the initial request, identical retry, unauthorized retry, and changed-payload retry. All 128 observations matched the Pass 16 serialized responses or errors, saved documents, and receipts after normalizing the generated typed effect ID. The existing 336 recovery, 1,656 conversion, and 326 slot-spending observations also matched. No gameplay corrections or unintended differences were observed. Removal of the dormant frontend operation producers is the contract correction.

## Pass 18 scope

Audit and tighten the `resource.adjust` and `resource.convert` payload contracts by registered subtype. Both commands already allowlist operation types.
