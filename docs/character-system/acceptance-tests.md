# Behavioral acceptance requirements

These specify future implementation tests, not tests run against a completed replacement. Use fixed rolls and world time. Every rejected operation must leave revision, pools, inventory and ledger unchanged. Cover unit logic, HTTP/persistence and frontend interactions at their appropriate boundaries.

## Exhaustive roster and progression matrix

Create legal level-one fixtures for all 18 origins × eight Callings. Assert the origin bonus applies once, no nationality restrictions, correct Health/saves/skills/equipment/spells and complete mandatory choices. For each of 32 Paths advance through every level 1–20: no Path before 3; exactly one owned Path required at 3; all four choices available to every origin; foreign Path rejected; exact parent and Path grants/upgrades at every scheduled level, including inherited features on otherwise empty levels.

Hardcode independent expected counts (8 Callings, 32 Paths, four per Calling) and schedules so omissions cannot shrink a loop silently. Check unique IDs and resolved references. Expected numbers must be calculated independently, not generated by the same rules functions under test.

For every ability and selectable clause: reject below unlock; accept at unlock; check ownership, required selections, equipment, action type, targets/range/duration, first/final expenditure, insufficient-resource rejection, Short/Long Rest behavior and every later upgrade. Passive/upgrade clauses must never spend a paid clause's cost. Test Reaction, Bonus Action, no-action and rest timing separately. For GM-adjudicated effects verify source, costs, accepted adjudication and persistent result without pretending to automate visibility or damage resolution.

## Feature-specific management

Triage locks survive different surgeons, target rename, retry and reload. Impossible Operation checks death within one minute, consent/body conditions and atomic one-counter/one-Channel/five-kit cost. Ghost salvage needs wreck evidence, once-per-rest counter and single-consumption credits. Relay destruction clears circuit benefits; test two-relay cap, teleport origin/destination and Discharge. Barrier placement, mitigation and free-use counters are independent.

Test all ten Metamagic options with exact costs, one/two-option stacking, Quickened restrictions, Heightened saves, Subtle materials and Transmuted damage. Test both Spell Mastery picks, independent Signature counters, folio discovery/copy/lost-folio recovery, Sorcerous Restoration once per Long Rest and Divine Intervention's level-20 2d4-rest cooldown. Cover both Gray Net prey/defense choices and permitted rest replacements. Cunning Strike cannot exceed Sneak dice; no duplicate Sneak Attack. Brutal Strike forgoes the required advantage and grants the correct choices. Evocation Savant choices occur at every newly unlocked slot tier, not just Path feature levels.

## Persistence, frontend and preservation

Complete the ten-step creator, save and reload with exact choice/stat parity. Canceling preview writes nothing. Missing choices block commits; stale/foreign errors preserve the draft. Every unlocked ability appears with full rules, costs, computed DC/dice, upgrades, source and unavailable reasons. Passive cards have no spend button. Click, reload and rest must reflect backend totals. Spell UI covers materials, free sources and Concentration; equipment UI covers equip/unequip, presets, quantities, ammo, Guard and missing-instance rejection.

Real development-Mongo tests must cover owner isolation, idempotency index, compare-and-set, cross-target transaction rollback, server-restart reload, strict schema and rules-version mismatch. Model doubles alone do not satisfy this gate. Browser review at 320/768/1440 pixels, both themes, keyboard navigation, accessible labels/live errors, long descriptions and table overflow. Compare recovered historical presentation. Verify login/logout, navigation, maps, campaign/session relationships, reputation/lore/assets and unrelated applications. Run relevant tests, lint and production build after implementation changes.
